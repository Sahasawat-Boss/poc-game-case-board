# แฟ้มคดีลอสโซรานเจลิส (Case Board)

เกมไขคดีจากฐานข้อมูลจริง **โดยไม่ต้องเขียน SQL สักตัว**
พี่น้องกับ [`sql-detective`](../sql-detective) — ใช้เมืองเดียวกัน ข้อมูลชุดเดียวกัน
ต่างกันที่วิธีที่ผู้เล่นเข้าถึงข้อมูล

|                    | sql-detective          | case-board (โปรเจกต์นี้)                  |
| ------------------ | ---------------------- | ----------------------------------------- |
| ผู้เล่นทำอะไร      | พิมพ์คิวรี SQL         | คลิกกรอง / กดเชื่อมแฟ้ม / ลากการ์ด        |
| ตันเพราะอะไรได้บ้าง | คิดไม่ออก **หรือ** เขียนไม่เป็น | คิดไม่ออกอย่างเดียว                |
| เบื้องหลัง         | SQLite ในเบราว์เซอร์   | SQLite ในเบราว์เซอร์ (เหมือนกันเป๊ะ)       |

เหตุผลที่แยกโปรเจกต์: เกมเดิมสนุกตรงการวิเคราะห์ แต่ด่านท้าย ๆ บังคับ window function
กับ recursive CTE ผู้เล่นเลยตันเพราะ*ไวยากรณ์* ไม่ใช่เพราะ*คิดไม่ออก* เกมนี้ตัดกำแพงนั้นทิ้ง
แต่เก็บการวิเคราะห์ไว้ครบ

## เริ่มใช้งาน

```bash
npm install     # postinstall คัดลอก sql-wasm.wasm ไป public/ ให้เอง
npm run dev     # http://localhost:3000
```

```bash
npm run verify  # ตรวจว่าทุกคดีไขได้จริงด้วยการคลิก (ไม่ต้องเปิดเบราว์เซอร์)
npm run smoke   # เล่นจริงในเบราว์เซอร์แบบอัตโนมัติ (ต้องเปิด npm run dev ไว้ก่อน)
```

## สองมุมมองของเกม

**🗄️ ห้องแฟ้ม** — ชั้นวางมี 12 แฟ้ม กดเปิดแล้วกรองด้วยเมนู ค่าที่เลือกได้ดึงมาจากข้อมูลจริง
ผู้เล่นจึงไม่มีทางพิมพ์ผิดจนได้ผลลัพธ์ว่างแล้วงงว่าตัวเองทำอะไรพลาด

**📌 กระดานผังคดี** — แถวไหนน่าสนใจกด 📌 ส่งขึ้นกระดาน ลากจัดวาง โยงเชือกแดง
กาชื่อคนที่มีข้อแก้ตัวออก การชี้ตัวคนร้ายทำจากกระดานนี้เท่านั้น ไม่ใช่ช่องพิมพ์ชื่อ

## เครื่องมือทั้งหมด แปลว่าอะไรในภาษา SQL

ผู้เล่นไม่ต้องรู้ตารางนี้ แต่คนดูแลโค้ดควรรู้

| ปุ่มในเกม                      | เบื้องหลัง                        |
| ------------------------------ | --------------------------------- |
| เปิดแฟ้ม                       | `FROM <table>`                    |
| เพิ่มตัวกรอง                   | `WHERE`                           |
| กดหัวคอลัมน์                   | `ORDER BY`                        |
| 🔗 เชื่อมแฟ้ม                  | `JOIN`                            |
| ⛔ สลับเป็น “ต้องไม่มีข้อมูล”  | `NOT EXISTS (...)` (anti-join)    |
| 📊 สรุปยอด                     | `GROUP BY` + `COUNT/SUM/AVG/...`  |
| เอาเฉพาะกลุ่มที่ได้ตั้งแต่ N   | `HAVING`                          |
| เงื่อนไข “มากกว่าช่อง …”       | เทียบคอลัมน์กับคอลัมน์            |
| เงื่อนไข “ช่วงเวลาในวัน”       | `substr(col, 12, 5) BETWEEN`      |

เครื่องมือพวกนี้ไม่ได้ให้มาพร้อมกันหมด — ทยอยปลดล็อกตามคดี (ดู `unlocks` ใน `data/cases.ts`)
และมีแถบ **“คำสั่งเบื้องหลัง”** ใต้ตารางให้กางดู SQL ที่การคลิกเมื่อกี้แปลออกมาได้
ใครเล่นจนคุ้นแล้วอยากไปต่อที่ `sql-detective` ก็มีสะพานให้

## เพิ่มคดีใหม่

1. ต่อ object ท้าย `TEMPLATES` ใน `src/data/cases.ts`
   ชื่อคนในเนื้อคดีเขียนเป็น `{{name17}}` ชื่อสถานที่เขียนแบบ canonical (เช่น `Old Town Wall`)
   ระบบจะแทนด้วยชื่อของรอบเล่นนั้นให้เอง
2. ถ้าคดีใหม่ต้องใช้เครื่องมือที่ยังไม่เคยโผล่ ใส่ไว้ใน `unlocks`
3. เพิ่มรายการตรวจใน `scripts/verify-cases.ts` แล้วรัน `npm run verify`
   — เขียน `QueryState` แบบที่ผู้เล่นจะประกอบได้จริง ถ้าคดีไขไม่ได้ด้วยการคลิก สคริปต์จะฟ้อง

ข้อควรระวัง: อย่าตั้งคำตอบเป็นค่าที่มาจากชื่อสถานที่ตายตัว เพราะชื่อสุ่มใหม่ทุกรอบ
ถ้าคำตอบเป็นสถานที่ ให้ใส่ชื่อ canonical แล้วปล่อยให้ `applyPlaces` แปลงให้ (ดูคดีที่ 5)

## เล่นซ้ำได้ไม่ต้องจำคำตอบ

เหมือนเกมเดิม — ทุกครั้งที่เปิด `/play` ชื่อคนและชื่อสถานที่ทั้งเมืองจะสุ่มใหม่
โครงข้อมูลและตรรกะของทุกคดีเหมือนเดิมเป๊ะ เปลี่ยนแค่ป้ายชื่อที่มองเห็น
ความคืบหน้า (คดีที่ปิดแล้ว) เก็บใน localStorage ส่วนกระดานผังคดีอยู่แค่ในรอบเล่นนั้น
เพราะการ์ดเก่าจะอ้างถึงชื่อคนที่ไม่มีอยู่แล้วในเมืองรอบใหม่
